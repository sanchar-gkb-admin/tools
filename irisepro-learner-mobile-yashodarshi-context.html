Learner mobile & Yashodarshi context

Two rulings, 25-Nov-2026. Each screen names its source. Sample learners are fictional.

A · The learner's registered mobile: captured, then visible to admins

Source: the ops lead, 23-Nov: "make the student's registered mobile number visible and accessible in the Superadmin dashboard." Prod, 25-Nov: 144 of 207 learners since 29-Jul have no mobile, and 143 of them are waiver learners added from school rosters who were never asked.

Ruling (Goutam, 25-Nov): capture at both ends: the admin adds it with the roster, and the learner or parent is asked at onboarding if it is still missing. One stored number, shown everywhere.
01 roster import→02 manual add→03 onboarding asks if missing→04 student page→05 enrolment page→06 list + search

B · Yashodarshi panel: who the learner is

Today the panel is blind (rule #80): pseudonym plus age, board, standard and stream. Name and institution are never shown.

Ruling (Goutam, 25-Nov): "show the student name, stream, institution if present and standard in the yashodarshi panel", shown everywhere, including while marking. This ends blind marking; rule #80 and the design docs are updated in the same change. The candidate code stays as a small reference so codes already quoted still work.
