01Six on-ramps, one trunk

The context changes the opening move and how much you skip. It does not change the flow.

So each lane gets its own opening and its own join point, then merges. Five parallel flows would mean editing the 5 Sep MCQ date in five places, and it would get edited in four.

Every terminal state is a HANDOVER. The bot never waits. · Link handed over → the app · · Handed to a human → the team inbox · · Community joined → the community · · Webinar registered → the session · · Stopped → nobody. Not one of them is a pending state. Nothing in this flow sits waiting for an outcome it cannot see — which is why there is no payment confirmation, no "did you pay?", and no abandoned-checkout recovery inside the bot. A conversation that waits is a conversation that has to be reconciled, and reconciliation is where a chatbot starts lying about state it does not own.
Terminal states, drawn explicitly. · STOP / "don't message me" → suppress every future send, confirm once, never again. Not a cold score — a flag. · minor-blocked → conversation stays open and friendly, measurement stops. · no opt-in → cannot be entered into any sequence at all, whatever the list says.

11Template inventory — the real timeline

Assume everything must be pre-authored and pre-approved. Then the only question that matters is: how many objects, and can we cut them?

Every bubble in this storyboard is static copy already — no variables except a name — so treating them all as templates costs the design nothing. It costs approval time, and each language is a separate submission because bilingual templates are rejected.

Two regimes — only one is expensive

Inside the 24h window — cheap
They messaged first: website "Hi", ad tap, or any reply. Meta permits free-form and interactive button/list messages here with no template approval.
Covers lanes A and B — and the entire qualification trunk, because by then they have replied.
Outside it — approved template only
Business-initiated. Ordered params, 24–48h per submission, ×2 for Kannada.
Covers lanes C (broadcast), D (webinar), E (checkout recovery) — message 1 only. After they reply, the window opens and the rest is cheap again.
⛔ That split is Meta's rule. Whether the AiSensy builder exposes free-form session messages, or forces every node to be a template object, is the vendor question — and it is unverified. Ask them directly; it changes the number below by about 3×.
