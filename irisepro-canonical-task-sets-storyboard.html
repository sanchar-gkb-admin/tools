Canonical task sets

One slot, many interchangeable tasks. Two levels of randomisation at unit mint: which task fills each slot, then what order the slots run in. These are the admin screens — what exists today, what changes, and what it takes to get 187 existing tasks into sets.

One hard prerequisite, from the code. Middleware/EnsureTaskAccess:43-46 authorises a task by joining challenge_task on challenge_id. A dealt variant lives in the learner's snapshot but not on the challenge pivot, so it would be 403'd mid-journey — and TaskDetailsController:962 fails silently: the page renders, no expires_at is stamped, and submit returns 422 timer_not_started. Slice D of the existing per-student-order plan (cursor + every gate onto TaskOrder::for($unit), one commit) must land first.
