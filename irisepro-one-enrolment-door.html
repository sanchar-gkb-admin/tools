Super Admin · enrolment · 4 Aug 2026

One door.
Enrolling creates the person.

Three admin paths could create an enrolment; only the batch door is used — 145 batches against one CSV import, ever. And one of them lets you create a person attached to nothing at all, which is a state nobody wants and the system has no use for. This is what changes on screen.

Before — two acts, three doors

Stream is a free-text box and the server demands an exact program_key. An admin types acharya foundation, the real key is acharya_foundation, and nothing on the screen says so.

And it can't reach the acharyas anyway. All three acharya streams exist only as demo challenges, and this door filters demos out. The 61 acharya enrolments in production were never made here — they were made in the batch door.

A person enrolled in nothing has no access and no purpose. The screen lets you make one by filling half the form, and nothing warns you.

Nothing is lost. The batch door could never create a person; the student door was never where cohorts were formed. Joining them removes a step rather than a capability.

Add Student returns 404, not just an unlinked page — a screen that is merely unlinked is still reachable by anyone with the URL in their history.

The same three inputs the CSV always took — Full Name, Email, Phone. The Stream and Plan columns are no longer needed, because the batch already names the programme. An old file still imports; those columns are simply ignored.

An email is an ACCOUNT, not a person. One parent, one address, several children — so a student is recognised by email and child name. Where that is still ambiguous the system stops and asks rather than guessing which child you meant.

One message, not fifty. A problem with the file is reported once, at the top, before anything is written — not as forty identical row errors after a half-finished import.

"Already with us" is the point. Ananya enrolling in a second programme gets a second enrolment against the same person — which is what 57 students in production already have, and what the roster must never turn into a second record.

Desktop only, deliberately. The Super Admin panel is used at a desk; no mobile screens are proposed here, so none are drawn.
