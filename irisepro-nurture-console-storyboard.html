The Nurture Console

Every green YOU DECIDE in Geeta ji's guide becomes a row she can edit here. Config is data; guards are code. So these screens let her change the words, the points and the timing — and show her the rules she cannot change, greyed out, so the boundary is visible rather than discovered.

Conditions are a picker, not a formula box

Every condition is chosen from a fixed list — stage · temperature · score · has tag · days since — joined only by AND/OR.

No free-text formulas, ever. The moment we allow score > 40 && … we have built a programming language with no tests and one user. A picker can be validated, explained and simulated. A formula box cannot.

Hi {{name}} — just so you know what to expect: it's 45 minutes, there's no sales pitch, and there's nothing to prepare. Your child is welcome but doesn't need to come.
This looks like a HELPFUL message — ₹0.145

The classifier is the highest-value widget on this screen. A 7× cost difference sits on one judgement call, and the honest test — "if you removed the offer, would they still want this?" — is easier to apply than a policy document. It shows the answer while she writes, not after the invoice.

"Give the map" is read most (361) but books least (38). People enjoy it and then do nothing — it may work better as a thank-you after booking than as a reason to book.
The read-vs-book gap is the insight this screen exists to surface. A message can be popular and useless. Without per-message attribution you would have concluded the free guide was working, because everybody opens it.

12 What this means for the build engineering

ScreenBacked byPhase
Touchpoints · bands · cadenceVersioned config rows. Pure data1
Locked rowsCode guards, rendered read-only. The UI reads a registry of guards — it never receives an editable flag for them1
Message inventory + editorConfig + BSP template state. Template creation is manual on AiSensy, so "Send to Meta" is a task, not an API call — unless we pick Gupshup2
Sequence builderConfig + the closed predicate grammar. No formula box2
SimulateReplay engine. Only possible because score/temperature are pure functions of (events, config version)2
Versions & rollbackImmutable published config + config_version stamped on every send1 — the stamp; 2 — the UI
Experiment resultsangle_key + angle_position + cohort on every send3
Phase 1 needs no console at all. The config can live as a versioned JSON file in the repo — free history, free review, free rollback, no UI to build. Build these screens when Geeta ji needs to change words without a deploy, not before. At ~400 people in nurture that day is closer than it was, but it is still not day one.
The one screen worth building early is Simulate. Everything else is convenience — Geeta ji could email a change and an engineer could apply it. But "what will this change do to real people?" has no substitute, and it is the difference between a config system that invites experimentation and one everybody is afraid to touch.
